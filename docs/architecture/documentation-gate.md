# 文档生命周期门禁

`npm run check-docs` 调用标准库 Python 实现 `scripts/check_docs.py`，默认检查自身仓库，`--root` 可用于独立验收 fixture。
代码复用自 koven-editors 提交 `17f0f1b2f9d6a9f53bcca29d8d08a8c091c4c338` 的检查器；
网站适配 SITE-V1-M 命名空间、渐进登记、活动 Spec 前置及非法 UTF-8 诊断，不新增依赖或网络请求。

## 输入与判定

- `docs/inventory.json` 为非空 ID→本地路径映射；正文 metadata 定义状态和关系，不重复保存实时状态。
- 库存和生命周期目录双向核对，防止删登记而静默漏查；metadata 放错目录也被发现。
- Spec／里程碑的归属、同类依赖、目录与状态、证据路径和必填章节一起检查。
- Spec 激活要求本地依赖 done、无 blocker；完成额外要求证据存在。里程碑完成要求依赖完成、至少两个真实子 Spec 且全部 done。
- 根目录入口与 docs 下 Markdown 的行内链接、引用定义和锚点被检查；远端链接、证据真实性、跨仓库输入及实际 CI 结论仍需独立核验。
- 只读取文件，不执行证据或来源脚本。检查失败退出 1；成功退出 0。

## 执行边界

PR／既有发布 workflow 在生成内容与构建前执行该门禁；`npm test` 自动发现治理变异测试。
测试使用独立文档树覆盖成功、错误身份／依赖／归档／证据和 CLI 失败，避免依赖当前 Spec 的具体状态。
没有修改网站内容源或页面；门禁成功不表示语言、服务或整个里程碑已交付。
