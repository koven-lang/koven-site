# SPEC-0001：文档库存与生命周期门禁

## 目标

网站的里程碑和 Spec 状态、归属、依赖、归档及证据失配时，本地命令和 PR 构建必须失败。

## 范围

属于 SITE-V1-M0；建立独立路径库存、正文 metadata、检查入口、意图测试及 CI 接线。
以 main `cea6afabb68ee167365b282bbe27be79165d10ec` 为基线；用户 2026-10-22 的持续实施授权覆盖本片。
复用 koven-editors 提交 `17f0f1b2f9d6a9f53bcca29d8d08a8c091c4c338` 的独立 Python 检查器，按网站渐进立项规则适配，不新增第三方依赖。

## 非目标

不改网站页面、内容源 ref、生成快照、语言规范或在线运行能力；不查询外部仓库状态，不证明证据内容真实。
不提前分配未来 Spec，不移动编辑器合同，不为纯文档历史补造功能 Spec。

## 行为合同

- docs/inventory.json 只登记 ID→路径；各合同首行 JSON metadata 是状态真源，正文有必填章节。
- 本地 ID：SPEC-四位数字、SITE-V1-M数字；不接受外部仓库 ID 冒充本地依赖。
- 路径必须在本仓库内；拒绝重复 ID／路径、未登记合同、坏链接／锚点、状态与目录不匹配。
- Spec 与唯一主里程碑双向归属；同类本地依赖存在且无环。跨仓库前置写正文与 blocker，人工核实。
- approved／in-progress Spec 的本地依赖必须 done，且不得有 blocker；draft 可以等待前置。
- done Spec 与 completed 里程碑必须有存在的证据文件、无 blocker、所有本地依赖完成；里程碑全部已登记 Spec 必须 done。
- 渐进立项时里程碑可以先登记一份 Spec；completed 时必须至少两份真实 Spec，不能靠空占位合同凑数。剩余工作暂留候选主题。
- 只有合法迁移到 archive 且同步库存／引用才接受 done；失败必须非零退出，不把空库存或无检查当作成功。

## 接口变化

新增 python3 scripts/check_docs.py [--root PATH] 和 npm run check-docs。
检查仅读取本地 UTF-8 文档、库存及证据路径；成功退出 0，问题退出 1 并输出可定位原因。
CI 在内容生成与构建前运行该命令；既有 npm test 同时执行治理负例与内容测试。

## 失败场景

漏项、重复、归属反向缺失、依赖环／不存在／类型错误、未完成前置、目录错位、缺证据／blocker、
错误 metadata 类型、不可读／非法 UTF-8 文档、路径越界、坏引用／锚点、空库存均需失败。

## 依赖

无功能 Spec 前置；复用已有治理及 Python 标准库，网站内容输入保持固定来源。

## 测试与验收

先在未适配的既有检查器上证明网站命名空间不被接受与活动 Spec 前置未受约束，再最小适配。
变异测试直接破坏独立 fixture 的业务合同，核拒绝原因；正例覆盖渐进立项、中文锚点、完整归档和 CLI 退出码。
带真实 KOVEN_SOURCE／KOVEN_REF 运行 npm test，避免把真实内容检查跳过；PR CI 验生成及构建。

## 完成条件

上述行为逐项有正反例；当前文档通过；独立审查无未决项；PR 精确 head CI 通过后按流程归档。
SITE-V1-M0 的 API／跨仓库合同仍可能未完成，本 Spec 完成不关闭整个里程碑。
