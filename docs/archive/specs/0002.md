# SPEC-0002：内容来源仓库身份一致性

## 目标

落实 ECO-V1-M0-S6 的网站首片：生成内容声明的仓库必须与配置和实际 Git checkout 一致，不能把其他仓库的内容标成 Koven 原仓库。

## 范围

基于 main `8e76608b0d3672a3a439cfd6a6c0b8018a5973ae`；授权来自持续实施生态路线图。
复用现有 resolve_source、sync_content 与内容快照，不改变当前配置的 repository/ref 或内容版本。

## 非目标

不启用或实施 v0.46、不更换来源、不增加在线执行、不声称工具链兼容验收完成。
Git remote 与配置匹配只证明输入身份约束，不认证发布者或判断仓库信任。

## 行为合同

配置仍为 GitHub owner/repository。导入前检查 checkout 的 origin，接受 GitHub HTTPS、scp SSH 和 ssh URL 的常用形式及可选 .git 后缀；仓库名比较不区分大小写。
缺失、非 GitHub、不支持的 remote 或仓库不匹配时失败，不写生成内容。
生成器从配置产生 source.repository，不保留硬编码仓库名；离线快照构建也必须与当前配置仓库一致。
ref 继续解析为精确 commit；本片不改变 nightly、tag、设计快照的选择或现有内容校验。

## 接口变化

复用 source.repository 的 HTTPS URL 形态，不改变前端数据结构。
现有 generate(root, ref) 调用和 CLI 保持可用；内部从 content-source.json 读取同一个仓库配置。

## 失败场景

配置格式非法、origin 缺失、不同仓库、其他宿主、带凭据 URL、离线快照来源与配置不一致均拒绝。
不把 remote 字符串或可能含凭据的完整 URL 写入诊断。

## 依赖

本地 SPEC-0001 已交付；消费既有已固定提交内容，不新增语言或上游接口前置。

## 测试与验收

运行 npm test（包含真实源）、check-docs、内容一致性、build、diff 检查；独立审查和 PR CI。

## 完成条件

全部定向合同与真实源验证通过、独立审查闭合、PR CI 通过后归档；SITE-V1-M0 整体联合验收另行判定。
